## Where it is NOT wired in or functioning (ranked by severity)

### P0 — blocks "operational"

1. **The live operator console has no backend.** Auth is a **synthetic demo session** (8 files reference `session/demo` / `demoMode` / `D2D_APP_PASSWORD`; the login file states it "keeps the deployed demo working _without an API_"). There is **no real authentication, no sessions tied to a real user store, no MFA, no SSO** in the deployed thing.
2. **No database of record in production.** The Prisma schema (39 models) exists, but the deployed app isn't backed by a live Postgres. The RLS tenant-isolation cutover is **uncommitted** (see P0-4). Production `DATABASE_URL` was deliberately held.
3. **`apps/api` is built but not deployed.** It has `infra/railway/railway.api.toml` + `Dockerfile.api`, 17 domain services, 39 models — but **only `web-operator` and `public-site` are live on Railway.** The backend the UI needs is sitting on disk, not running. Result: the front end can't talk to it because it isn't there.
4. **The security floor is uncommitted / unmerged.** `git status` shows **56 modified files** not committed — including the WS6 RLS cutover and `apps/api/src/domains/auth` changes and 11 API integration tests — **plus 4 unmerged `fix/soc2-p0/p1` branches** (BFF-auth-verify, RBAC-escalation, unmask-tenancy, auth-fail-closed). The multi-tenant isolation + auth hardening that makes this safe to run with real data **is not landed.**

### P1 — blocks real revenue / real campaigns

5. **No money movement.** The MiCamp payment adapter (WS2) is **pending/blocked** (no spec/sandbox creds). There is no real processing, settlement, or payout path wired.
6. **Front end mostly renders inline sample data.** In `web-operator`, **32 files carry inline `const DATA = [...]` arrays** vs **18 files that call an API**; only **6 BFF route handlers** exist and **3** proxy to the real api. So most screens are display-only mockups, not live data.
7. **The "Marketing Studio" and "Knocker iOS app" don't exist as apps.** `apps/marketing-studio` = 1 file, no package.json. `apps/knocker-ios` = 7 files, no native project. What you've seen are **UI screens inside web-operator**, not a delivery engine or a shipped app. (The world-class public-site phone mockups are exactly that — mockups.)

### P2 — quality / coverage

8. **Thin automated coverage:** 24 test files for ~92k LOC of first-party code. (Note: the unmerged SOC2 branches add the security tests — another reason to land them.)
9. **57 `placeholder` references** — almost all benign UI placeholder text / empty states (roster, marketing-studio screens, public changelog/signup), not broken logic.
